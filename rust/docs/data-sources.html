Data sources and column mapping ​

Before constructing a loader, give every matrix a common integer vocabulary. The resulting DataSource describes where rows live and what their columns mean; an OutputSchema chooses the columns and dtype delivered to the consumer. If you only need one file's selected rows, the simpler storage selection uses a direct source-to-output map.

Register matrices ​

DataSourceBuilder::new(vocab, page_size) declares the shared vocabulary size and I/O page size. add_cpk(path, to_std) registers a complete matrix stream; add_cpk_region(path, offset, length, to_std) registers an embedded stream. build() returns an immutable DataSource, normally shared with Arc.

to_std must cover every source column. Entries are distinct standard ids in [0, vocab), or UNMAPPED for dropped columns. All registered streams must use the builder's page size: a power of two from 512 through 65536 bytes.

Registration reads stream directories and chunk metadata, not every row's values. It is a setup step: register all inputs, call build, then reuse the immutable source when creating loaders and plans.

CD3D is missing from matrix B. In matrix A, it is present even if a particular CSR row omits it, which represents a zero value.

Use with_default(f64::NAN) in floating-point dense outputs to distinguish missing dimensions from present zeros. with_default_bytes sets an exact little-endian default, including large integers.

A zero value is not a missing column

The map declares whether a dimension exists for the entire matrix. An omitted CSR entry is a zero in an existing dimension. Choose a nonzero default such as NaN only when downstream code needs to distinguish the two situations.

Global cell ids ​

Matrices receive consecutive CellId ranges in registration order. DataSource::matrix_cells(index) returns the matrix's first global id and row count. Sampling must produce ids in this global space.

CellId is u32. The .cpk format's u64 row count does not imply that one loader data source accepts arbitrary u64 cell ids.

For two registered matrices with 4 and 3 rows, their ranges are [0, 4) and [4, 7). Matrix B local row 1 is global cell 5, regardless of the requested output panel. Obtain the actual base through matrix_cells; do not use a matrix index as a cell id. Access sequences explains how global cell ids become requested positions.

Input identity and direct I/O ​

Registration records each file's device, inode, size, and modification time. Loader::new and Loader::prepare check that identity to reject changed inputs. Keep input files immutable during a run as well.

direct_io(true) opens record data with O_DIRECT; metadata reads remain buffered. Enable it only when the filesystem and embedded-stream alignment support the required reads. Guide examples use direct_io(false) for portable small-file execution.

Check registration failures first ​

FailureCheck before changing the loader
