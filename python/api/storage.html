PyCellPack/API

Storage API ​

Use Store for lazy matrix access, Writer for incremental encoding, and File when you need embedded regions or chunk metadata. For an executable selection and streaming-write workflow, see matrix access.

python
from pycellpack import CSR, File, Store, Writer, read, write, compress
from pycellpack.cellpack import GeneMap, ReadOptions, ReadSelection, ReadWorkspace
from pycellpack import io

Select an interface

  • Select positions and decode matrix values.Store / read→Store retains a lazy view; read returns an array immediately.
  • Reuse metadata and caller-owned output.ReadSelection→Choose exact dense extents or capacity-based CSR buffers.
  • Encode a complete matrix or row stream.Writer / io.write_cpk→Writer is incremental; write and compress return Stores.

Views and selections ​

OperationContract
store[cells, genes]Orthogonal, axis-preserving selection; both axes support slices, integers, integer arrays and boolean masks
store.astype(dtype)Choose decode dtype without decoding; copy does not force materialization
store.copy()Return the same immutable view
store.map_genes(gene_map, n_genes=None)Map each current column to a distinct output position; unfilled output positions read as zero
store.prepare(read_options=None)Prepare reusable metadata; repeated columns are rejected
store.read(format=None, ...)Decode in stored format by default; "dense" returns ndarray, "csr" returns CSR
store.iter_batches(batch_size=4096, ...)Decode successive view rows; batch size must be positive

Order and repeated positions are preserved. Negative integer positions and negative-step slices follow positional indexing. Boolean mask lengths must match their current axis. Selection arrays exposed by cells and genes are read-only; genes=None means every source column in order. Strings are not gene or cell selectors: the stream stores no names.

For gene mapping, GeneMap owns the validated source-to-output map. cellpack.selection.as_gene_map also accepts an integer vector or a dict from current source positions to targets. The map covers every current column; -1 or scans.UNMAPPED drops a column, kept targets are distinct and below n_genes. This map assigns output positions, whereas a DataSource map assigns standard vocabulary IDs; see gene alignment. normalize_rows(rows, size) produces contiguous uint64 positional IDs.

Store(file, shape=...) requires its first dimension to equal stream rows and the product of trailing dimensions to equal stream columns. Only dense streams support more than two dimensions; those views allow row selection and dense reads only. Stores are read-only: materialize before assigning values.

Dtypes and materialized results ​

Supported value dtypes are uint8/16/32/64, int8/16/32/64, float32 and float64 in native byte order. A view/selection dtype requests conversion during decoding; compression alone preserves stored value bits. Conversion can lose precision.

read_dense, toarray and np.asarray(store) produce dense NumPy arrays. read_csr produces the package's NumPy-backed CSR without requiring SciPy. to_memory converts sparse output to a SciPy csr_array; tocsr always returns that SciPy type. CSR.to_scipy() requests shared storage, so later mutation of shared buffers can affect both representations.

Prepared reads and buffer extents ​

File.prepare_read(rows=None, *, gene_map=None, n_genes=None, dtype=None, read_options=None) reads selection metadata and returns ReadSelection. shape, dtype, capacity_nnz and io_summary describe the prepared result. Omitting output storage allocates arrays; supplied buffers follow these rules:

ReadRequired outputReturned storage
selection.read_dense(out=...)ndarray with exact selection.shape and selection.dtypeThe supplied array itself
selection.read_csr(out=...)CSR with matching shape, or (indptr, indices, data)CSR sharing supplied buffers; indices/data trimmed to actual entries
CSR indptrExactly rows + 1 elementsFinal value gives actual stored-entry count
CSR indices, dataCapacity for selection.capacity_nnz; data dtype matches selectionUnused trailing capacity is not output data

capacity_nnz is source-based capacity, not an exact mapped count: column filtering can reduce the returned CSR.nnz. Explicit sparse zeros remain stored entries. Allocated CSR indices/offsets use index_dtype=np.int64; int32, uint32 and uint64 are also supported. Caller-supplied indices additionally accept uint16, while row offsets require one of the four allocation types. The chosen integer widths must hold the resulting indices and offsets.

Outputs must be native-endian, aligned, writable and C-contiguous. Inputs, outputs and scratch must not overlap where native calls reject overlapping regions. Do not mutate or resize arrays borrowed by a native call, or read an output concurrently with its write. A ReadWorkspace retains scratch and permits one active read; use separate workspaces concurrently. After any failed read, discard potentially partial output.

Allocating Store reads can expand repeated selected columns. Such a view cannot prepare() or write CSR into caller-supplied buffers; dense out= remains supported. See the worked buffer example.

Payload read policy ​

strategy"auto"Compare range/whole-region read costs; "ranges" or "whole" forces a policy

ReadSummary reports record_bytes, read_bytes, requests and whole_chunk_bytes for one payload execution, excluding metadata preparation. These are application read estimates, not physical device traffic or calibration.

Writing and publication ​

Writer defaults are format="csr", chunk_rows=4096, page_size=4096, options=None, workers=None, atomic=False. write, compress and io.write_cpk instead default stored format to their input layout. Page size is a power of two from 512 through 65536 bytes; chunk_rows counts encoding rows. options accepts scans.EncodeOptions.

Every append(matrix) must match declared dtype and width. Dense or sparse batches can feed either stored layout. NumPy buffers are normalized; SciPy sparse inputs are canonicalized by sorting and summing duplicates. Package CSR/SparseRow inputs must already have sorted, distinct column indices per row. Explicit masked values must be filled before encoding.

ActionLifecycle
appendEncode more rows in order; stream is unfinished
end_chunkEnd the current encoding chunk early
finish / successful context exitFlush/finalize, then publish an atomic destination; returns None
abort / exceptional context exitClose unfinished work and discard atomic staging

Writers belong to their creating process. Without atomic mode an existing path can be truncated. atomic=True stages beside a regular destination and replaces it only after success; abort preserves the destination. Existing permission bits are preserved; a new atomic file uses mode 0600. Atomic publication does not promise persistence across power loss. Keep a completed stream immutable while readers or loaders use it.

Encoding and decoding release the GIL and use native worker threads. workers=None uses available CPUs, capped at 32 by default; the nonempty PYCELLPACK_WORKERS environment value overrides that default. Explicit counts and environment overrides must be positive and are capped by available CPU capacity, including affinity/cgroup quota. They are not fixed to the default 32-worker ceiling.

File regions, chunk access and identity ​

offset and length bound an embedded encoded stream. File.chunks returns its directory. read_chunk(chunk, out=None, metadata_only=False) reads encoded bytes, accepting negative chunk indices; chunk_meta(chunk) parses metadata using the stream dtype. Chunk APIs expose encoded components rather than materialized matrices; see codecs for record operations.

A File retains the opened descriptor and recorded device/inode identity. After path replacement, existing native reads use the original file; is_current reports whether the path still names it. to_bytes() rejects a replacement, and unpickling rejects a changed identity. File.from_bytes copies into anonymous storage; such Files pickle by copying their encoded bytes. Stores pickle their file and composed view. Exporting the whole region can require a large buffer.

Invalid types/selectors/buffer declarations raise TypeError, IndexError or ValueError as appropriate; file failures raise OSError. Those checked errors do not validate arbitrary trusted record bytes. Keep encoded data paired with its metadata, and do not modify files in place during reads.

Store ​

python
Store(source: File | Store | str | PathLike, *, shape: tuple[int, ...] | None=None, dtype=None)

An immutable, lazily indexed view of one CellPack stream.

Rows are cells. Each output column is a stored column or an absent one, which reads as zeros, so a Store can present a stream in a panel the caller lays out. Columns are addressed by position only. Views come from:

  • store[cells, genes]: orthogonal selection, as in AnnData or h5py. Integers keep their axis. Both axes take slices, integers, integer arrays (any order, repeats) and boolean masks.
  • map_genes: place columns by a caller-given column → panel map.
  • astype: convert values while decoding.

None of these read data. read, read_dense and read_csr decode into NumPy / ~pycellpack.cellpack.CSR (into caller buffers with out=); prepare returns a ReadSelection for repeated reads; to_memory, toarray, tocsr and np.asarray return NumPy / SciPy objects. Higher-rank dense arrays stored with flattened trailing axes take their logical shape and select cells only.

Writer ​

python
Writer(path: str | PathLike, n_cols: int, dtype, *, format: str='csr', chunk_rows: int=4096, page_size: int=4096, options: EncodeOptions | None=None, workers: int | None=None, atomic: bool=False)

Streaming stream writer. A stream becomes readable after finish().

append takes dense or sparse rows whatever the stored format; the native writer converts them. Whole chunks within one append are encoded by workers threads (default: one per CPU, at most 32); the file is identical to a serial write. Append many rows at a time to let chunks encode concurrently.

With atomic=True, a sibling temporary file is published only after finish succeeds; abort leaves the destination untouched. This requires a regular filesystem path and does not guarantee power-loss durability. New atomic files are private (mode 0600); existing permission bits are kept.
