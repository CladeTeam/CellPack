PyCellPack/API

Process functions API ​

ProcessFn binds native row callbacks, and OutputLayout describes their fixed output record. Read the guide for a complete CPU preset workflow and the runnable program for packed CUDA transfer.

python
from pycellpack.loader.process_fn import ProcessFn, OutputLayout, compile_library, presets

Find the contract you need

  • Choose an exported library, source build or Numba callback.Bind native code→Code ownership and configuration identity are separate requirements.
  • Define field offsets or retain processed results.Read named output→A layout describes a fixed record; NumPy field views keep its slot leased.
  • Use scGPT, Geneformer, UCE or STATE SE.Configure a preset→Tables follow schema output order, with float32 mapped input.

Derived library identities include file contents, function names, delivery mode, partial-row declaration and key. Numba identities also include function source or bytecode and the Numba version; cover any globals or closures in your key. Addresses need an explicit identity. Supplied context without a key or explicit identity is rejected.

process.schema accepts dtype, id, name, default and scratch_bytes in addition to out_ids. OutputSchema(process=...) infers row_bytes from a declared layout and rejects a conflicting explicit size. Without a layout, use its explicit row_bytes interface; schema() and unpack() then raise ValueError.

Compilation and reconstruction ​

compile_library accepts language, name, compiler, std, optimize, flags, include_dirs, defines, depends, cache_dir and force. Compiler selection uses the explicit choice, then CXX/CC, then supported platform drivers. The build cache includes sources, compiler identity, flags, ABI/preset headers and declared dependencies. List your additional included files in depends; they are not discovered as an arbitrary transitive dependency graph.

A compiler is resolved even for cached source builds. from_library can use an already built library without compiling. Recipe-based bindings pickle when their arguments do: source recipes rebuild from cache, library recipes reopen a path and named symbols, and supported Numba recipes reconstruct callables. Raw addresses, hand-made capsules or unsupported owner/context configurations do not provide a portable recipe. Preset recipes retain table values and rebuild native pointers in the receiver.

For generic factories, an explicit owner or integer user_data disables the automatic recipe, even if the owner would itself be picklable. Library/source recipes also require a path and named exports. Use a reconstruction factory for such pointer-owning configurations instead of sending the live object.

OutputLayout and field views ​

OutputLayout(fields, align=True) accepts NumPy structured dtype declarations, including explicit offsets and itemsize. Fields must be named, nonempty, native-endian numeric values within the record. Default C alignment includes tail padding. align=False describes a packed layout. The declaration must match the native callback; it does not guard that callback's output writes.

InterfaceResult
layout.dtypeStructured dtype with field offsets, shapes and padding
layout.namesTuple of field names in declaration order
layout.offsetsName → byte offset within the record
layout.row_bytes / process.row_bytesComplete padded record byte size
layout.unpack(raw, copy=False) / process.unpack(...)Dictionary of named NumPy fields

raw must be a NumPy uint8 array shaped [..., row_bytes]; its byte axis is contiguous, while leading axes may be strided. Scalar fields have the leading shape; array fields append their declared field shape. The usual source is batch.region(name).

With copy=False, fields may be strided or unaligned and retain raw storage and its slot lease, including after Batch release or Run closure. copy=True gives independent aligned C-contiguous arrays. Retaining every batch's field views can fill the output ring and block production. This helper accepts host NumPy arrays, not CUDA tensors. See ring ownership.

For explicit nonblocking H2D, retain the packed host view and host Tensor until the copy completes, then release them. Submitting the copy alone does not finish reading the slot. Device field views retain device storage; coordinate their CUDA streams independently. The CPU/CUDA program shows the complete lifetime sequence.

Callback input and ABI ​

ProcessFn.include_dir() and the module-level include_dir() locate process_fn_cabi.h, whose capsule name is pycellpack.process.v1. The context contains logical sequence position, global cell ID, schema index, input dtype and user_data. Callback values have already been converted to the schema dtype; column numbers address the mapped output panel. Every schema at one position sees the same position value; schema is its vector index, not application id.

DeliveryRequirement
"csr"CSR callback; columns can be unsorted and list stored elements only
"dense"Dense callback; present omitted values are zero, absent source dimensions receive the schema default; factories reject partial_rows=True
"auto"Equivalent CSR and dense callbacks; internal layout/route choices may change which one runs
Partial CSRNull column/value pointers require the supplied resolver; positions address stored elements, not output dimensions

CSR omissions alone do not identify whether a dimension was missing or zero. Use a distinguishing dense default or application-owned source metadata when that information matters. Partial-row resolve accepts repeated/out-of-order element positions; each must be below nnz. Null positions with count == nnz request all elements in order. Its row and output pointers are valid only for the call; propagate a nonzero resolver status.

Callbacks may run concurrently. Write within row_bytes and scratch_bytes, retain no borrowed pointers, and prevent exceptions or unwinding from crossing the C ABI. Native write bounds are the provider's responsibility. A nonzero callback status fails the run as a RuntimeError; it is a provider-defined code.

Model presets ​

All four factories return ProcessFn with a declared layout, input_dtype=float32 and out_dim=len(tokens). Schemas reject incompatible mapped dtype or width. Each token and auxiliary-table entry addresses one schema output dimension in out_ids order, rather than a standard ID or original file column. Tables are copied into immutable contiguous storage. Negative tokens exclude dimensions.

Let L=length, Q=positive+negative for UCE and Q=positive+negative+shared for STATE SE.

FactoryRequired tables / special IDsFields per row
scgpttokens; pad_token, cls_tokengenes int64[L], values float32[L], targets float32[L]
geneformertokens, medians; pad_token, cls_token, eos_tokenids int64[L], length uint32
ucetokens, chroms, starts; pad_token, cls_token, chrom_offset, chrom_close_tokenids int64[L], loss_ids int64[Q], labels float32[Q], length uint32
state_setokens; global_sizeids int64[L], tasks int64[Q], targets float32[Q], counts float32[L], total float32

Medians, chromosomes and starts have the token-table width. Tokens must be a nonempty integer vector with at least one nonnegative entry. Factories validate option domains and table dimensions; per-cell content can still fail in native execution. Geneformer excludes nonpositive medians. UCE requires at least two eligible expressed genes in a cell and sufficient sentence capacity; the header also defines masking-related status codes. STATE SE requires nonnegative tokens below global_size; batch groups consecutive access positions for shared query draws and cls_index indexes the eligible panel.

Defaults and exact sampling arguments are listed in the declarations. They implement the shipped templates rather than loading a checkpoint's preprocessing configuration. Factories compile C++17 templates and pass build keywords to compile_library; native/Python struct sizes and offsets are compile-time checked. Headers are under include/template/{scgpt,geneformer,uce,state_se}.hpp.

Instantiate a C++ template directly
cpp
#include "template/scgpt.hpp"
struct Config : pycellpack::preset::ScGptDefaults {
    static constexpr uint32_t length = 1200;
};
PYCELLPACK_EXPORT_PROCESS_FN(scgpt, pycellpack::preset::ScGpt<Config>)

Bind scgpt_csr and scgpt_dense with ProcessFn.from_source. Supply the header's exact runtime-table struct through user_data, a key covering its contents, and a matching OutputLayout. template/common.hpp adapts these models to the C ABI.

Errors ​

Invalid layouts, identities, delivery modes, table dimensions and options raise TypeError or ValueError. Missing compilers raise CompilerNotFoundError; compilation failures raise ProcessBuildError; library loading or missing exports raise ProcessLibraryError. Execution and callback failures surface during iteration or joining. After failure, use the run recovery rules rather than consuming partially written output.

Declarations ​

Complete declarations and members

ProcessFn ​

A provider-owned pycellpack.process.v1 capsule (see process_fn_cabi.h): a CSR and/or a dense function turning one cell's row, mapped to the schema's output dims and converted to its dtype, into the cell's fixed-size output.

Four ways to build one: ProcessFn.from_source compiles C/C++ code and binds it; ProcessFn.from_cfunc binds numba @cfunc functions (or compiles Python functions as such); ProcessFn.from_library binds the functions of a library built elsewhere (an MSVC DLL, say); the constructor takes a vtable capsule made by hand.

Row semantics: an output dim the cell's matrix has a column for is present (its stored value, or 0 where the record stores none: CSR drops zeros, so they are expression values); an output dim with no matching column is missing; a column no output dim takes is dropped. CSR rows list stored elements only. Dense rows hold 0 at present zeros and the schema's default at missing dims, so a default no value takes (NaN, the dtype's maximum) lets a dense function tell missing dims apart; a CSR function can instead keep each dataset's genes in its user data and find the cell's dataset from the context's global cell id.

row_format picks the rows delivered: "auto" (both functions) gives CSR records as CSR rows; dense records use internal throughput thresholds based on dimensions, dtype conversion, value coding and cache state. Cached dense records may compact to CSR once at admission. "csr" or "dense" always delivers that format and needs only that function (the other vtable entry may be NULL).

The functions are native and thread-safe, write only their cell's output and their scratch (nothing is checked), and must compute the same output from the same row. identity versions the functions and all retained configuration; owner can retain a shared library, vtable or parameters. partial_rows declares that the CSR function resolves rows given without columns and values.

A function built by from_source, by from_library from a library path and exported names, or by from_cfunc from picklable functions pickles as that recipe (the other process rebuilds it, from the build cache for sources); one bound from a hand-made capsule or raw addresses names this process's memory and does not.

ProcessFn.from_library ​

python
ProcessFn.from_library(library, *, csr=None, dense=None, user_data=None, key=None, identity=None, row_format=None, partial_rows=False, owner=None, output=None)

Binds a shared library's process functions, without a hand-made vtable or capsule.

library is a path or a loaded ctypes.CDLL; csr and dense name the exported functions (or give ctypes functions or addresses). The row format defaults to what they cover: both "auto", one alone that format. user_data is passed to every call: a ctypes object (a Structure, an array) or a numpy array, both kept alive, or a raw address the caller keeps valid; owner retains anything else it points to.

The identity defaults to a hash of the library file, the function names, the row format, partial_rows and key, which must describe what user_data holds (numbers, strings, bytes, numpy arrays, ctypes objects, or lists/tuples/dicts of them); give identity instead to set it directly. Raises ProcessLibraryError when the library cannot be loaded or lacks a function.

output is an OutputLayout or structured dtype specification for the function's fixed output record. It enables schema() and unpack() and must agree with the function's actual writes.

ProcessFn.from_cfunc ​

python
ProcessFn.from_cfunc(*, csr=None, dense=None, user_data=None, key=None, identity=None, row_format=None, partial_rows=False, owner=None, output=None)

Binds process functions written in Python with numba.

csr and dense are numba @cfunc functions with the signatures returned by pycellpack.loader.process_fn.numba_bindings() (CSR_SIGNATURE, DENSE_SIGNATURE; int32(voidptr) is accepted too), or plain Python functions, which are compiled with those signatures here. user_data, key, identity, row_format, partial_rows and owner are as for from_library; the default identity hashes the functions' source (or bytecode), the numba version, the row format, partial_rows and key, which must also cover globals or closures the functions read. Raises ProcessBuildError when numba cannot compile a function, TypeError for a cfunc of another signature.

OutputLayout.unpack ​

python
OutputLayout.unpack(raw: np.ndarray, *, copy=False) -> dict[str, np.ndarray]

View uint8[..., row_bytes] as named arrays without copying.

The last axis must be contiguous; preceding axes may be strided. Views retain their source, including a batch's slot lease. compile_library ​

python
compile_library(sources=(), *, code=None, language=None, name=None, compiler=None, std=None, optimize='-O3', flags=(), include_dirs=(), defines=None, depends=(), cache_dir=None, force=False) -> Path

Compiles process function sources into a shared library; returns its path.

sources are C or C++ files (by suffix); code adds inline source text in language, C++ unless language="c" (one driver invocation compiles every input as one language, so inline code joins C source files only when it is declared C). The process headers (process_fn_cabi.h and the model templates under template/) and every source file's directory are on the include path, before include_dirs. flags are passed to the compiler as is (say ["-march=native"]); defines maps macro names to values (None: defined without a value).

The library is cached under cache_dir (default $CELLPACK_HOME/process-libraries) by everything that shapes it: the compiler and its version, the command options, the sources, the process headers and the files in depends (headers or included sources not listed in sources). A cached library is reused unless force; concurrent builds of the same library are safe. Raises CompilerNotFoundError when no GCC/Clang driver is usable and ProcessBuildError (with the command and the compiler's messages) when compilation fails.
