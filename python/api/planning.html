PyCellPack/API

Planning API ​

Use this reference for mode selection, option units and plan identity. The planning guide compiles, saves and executes a small plan while checking its decoded result.

python
from pycellpack.loader.opt import PlanOptions, Plan, PageTrace, CostModel

Select a planning interface

  • Deliver batches under a selected modeLoader.start→None disables planning; Plan executes fixed decisions; options compile online.
  • Inspect compilation without loading valuesLoader.compile / compile_stats→Retain a Plan or collect online compiler observations.
  • Inspect or compare cache decisionsPlan / PageTrace→Use bound-plan replay for actions, and the serial page optimum for a narrower reference.

Execution and compilation modes ​

CallPlanning behaviorReturns
start(accesses, plan=None)No planned cacheRun
start(accesses, plan=plan)Execute a compatible fixed PlanRun

start(accesses, plan=byte_budget)Resolve default options/costs and compile onlineRun
compile(accesses, options, online=False)Whole-sequence compilationPlan

compile_stats(accesses, options)Online compilation without output delivery or retained decisionsOnlineStats

compile accepts PlanOptions or a byte budget and materializes computed Accesses into a stored sequence. compile_stats and online start can generate intervals without retaining all cell IDs. Access counts are position-first, schema-second and must be divisible by the loader's schema count. See access sequences for composition and deterministic callbacks.

plan_options(cache_bytes, cost="auto") returns frozen PlanOptions with the loader's window as gap. Automatic cost resolution consults saved records and defaults; it does not calibrate hardware. Pass a CostModel explicitly or cost=None for equal-valued page hits. Constructing PlanOptions directly does not resolve costs automatically. The loader fills unset gap/thread values in a copy, leaving your object unchanged.

PlanOptions parameters ​

FieldDefaultContract

block_pagesNoneOptional candidate read width in 2–128 pages; requires costs

Automatic threads is one per usable CPU offline, or a quarter of executor workers online, bounded to 1–16 and the usable CPU count. An explicit positive value bypasses that automatic cap. cpus influences the usable count and pins compiler threads; it does not configure executor workers.

rows=True with objective="misses" is disabled by the engine, rather than selecting a mixed row/page miss objective. The requested row mode still requires a cost model during validation. A zero-byte plan still compiles and uses a PlanRing; choose plan=None to disable planning. Global row selection requires effective row caching over a fully available stored sequence and full horizon; use the incremental policy for finite-horizon or generated streams.

Slots versus accesses ​

One slot represents S × slot_rows accesses, where S is the number of loader schemas. The gap reserves frames before their admission; loader window controls execution lead and may not exceed that gap. Neither setting is the output ring's slots capacity.

Configured horizon is converted to accesses. With no explicit horizon, online lookahead starts at twice the source cell count per schema. The engine raises it to at least distance + chunk, then caps it at sequence length (at least one for an empty sequence). Consequently OnlineStats reports the effective horizon, which can differ from the configured request.

Plan identity and serialization ​

A Plan binds graph/source identity, column mappings, schema/process identities, schema order, slot_rows, and the exact access sequence. Reordered accesses or a different schema require recompilation. Ring slot count and consumer world size are not plan fingerprints; execution must still satisfy the loader's layout, window and ring contracts. Changing source files in place is outside the immutable input contract.

Plan.write(path) and Plan.open(path) use CPKPLAN1 files. to_bytes and from_bytes use the same format; a Plan also pickles through those bytes. The file stores fingerprints, residency decisions and the optional cost model. Opening parses the file, while start or replay checks compatibility with an actual loader and sequence.

For a freshly compiled Plan, summary contains serial replay counts. A restored Plan's summary is initially empty and is populated when a loader first verifies it through start or replay; inspect it after that step. online_stats belongs to a compile(..., online=True) result and is not retained by the plan file or pickle. Keep those observations separately if you need them.

residencies() returns arrays in admission order: kind (0 page, 1 row), key (global page ID or cell ID), start, end, offsets and frames. Residency i uses frames[offsets[i]:offsets[i + 1]]; start/end address accesses, not positions or batches. cache_bytes is the original budget and cache_frames is its whole-page capacity, not measured resident memory.

replay(..., cost=other_model) prices the same actions with another compatible model without changing the Plan or its stored summary. PlanSummary seconds are modeled; OnlineStats separates modeled seconds from compiler/wait wall seconds. Use executed RunStats for run observations.

Costs and reference comparisons ​

CostModel prices request capacity, byte bandwidth, worker physical cores, cached-row memory traffic and operation costs in core-seconds. Rates must be positive and finite, costs finite and nonnegative, serial in [0, 1], and bucket >= 1. Output records must match the loader's outputs. Compilation and replay check model compatibility; constructing a dataclass alone is not that validation.

to_dict / from_dict use the versioned native JSON field names; save writes JSON by sibling-file replacement, and load reads it. Required resource rates remain required; omitted optional fields use current defaults. Neither operation measures hardware. For resolution, record provenance and calibration, see statistics and cost records.

PageTrace.from_pages(pages, universe=None) normalizes a one-dimensional nonnegative uint32-range page sequence; the default universe is maximum ID + 1, or zero for an empty sequence. from_source(source, accesses) expands the pages needed by those global cells. optimum(capacity_pages) returns CacheSummary for serial Belady replacement. Its capacity counts pages, and its model excludes reuse-gap reservation, execution concurrency, decoded rows and management costs. It is not an optimal mixed page/row plan.

Validation and declarations ​

Invalid Python enum/count declarations raise ValueError; native checks also validate the resolved gap, horizon, frame count, CPU indices, cost model and plan binding. I/O errors opening or writing a plan raise OSError. Keep outputs and records from failed runs out of downstream results; lifecycle recovery is covered by rings and runs.

Complete declarations and members

PlanOptions ​

What a plan is compiled for. gap is the reuse gap in slots (default: the loader's window); runs of the plan execute within a window of at most it, and every residency reserves its frames from that far before its admission. rows caches rows too (page+row; needs a cost model), chosen by row_policy: "incremental" (each reuse decided as it arrives, against a shadow price of capacity learned from the pages) or "global" (rows first over the whole stored sequence; offline only). block_pages merges adjacent admissions into reads of 2 to 128 pages (needs a cost model). horizon bounds, in slots, the reuse intervals an online plan considers (at least gap); chunk is how many accesses the online compiler advances, freezes and publishes at a time. objective minimizes the modeled time ("time", the default) or page misses ("misses"); cost prices the decisions and is required for rows and block_pages.

threads=None resolves when a loader uses the options: offline, one per usable CPU (cpus if pinned); online, a quarter of the loader's workers; both at most 16. cpus pins the compiler threads (empty inherits the calling thread's CPUs).

CostModel ​

The loader's resources on one machine and the work it does (see cellpack::opt::model).

Four resources serve a run: the device's read requests (iops) and bytes (bandwidth), the workers' physical cores (cores) and main memory traffic of cached rows (memory_bandwidth). Work is in core-seconds: per access (access), per read request (request), per access the online compiler takes from the workers' cores (compile, online plans only), decoding (input), cached rows (rows) and each output (outputs, keyed by the loader's output names, or by position; convert adds a per-element cost for each conversion class, CONVERSIONS). A window of bucket accesses takes its device time (the longer of requests and bytes) or its core time, whichever is longer, plus serial of the shorter; a longer memory time overrides that sum. provenance records where each part came from (see pycellpack.loader.costs.resolve); it is not compared. The rates are positive and finite, costs finite and nonnegative, serial in [0, 1], bucket at least 1, and outputs has one entry per loader output; compilation and replay reject a model that breaks this.

to_dict/save write JSON in the native field names (outputs as a list in mapping order, each with its name), which the Rust crate reads with its serde feature.

PlanSummary ​

A plan's serial replay: page uses and hits; read requests and bytes; residencies and extra admission reads (block_reads); decoded records, their elements and those in a cold chunk; row hits and admissions with their elements and payload bytes; per schema (in loader order) the elements mapped, rows filled, process and partial calls; elements per conversion class; the most cache bytes held (serially, and reserved from each admission's reuse gap); modeled core-seconds (worker_seconds). Per quarter of the sequence (one epoch of a 4-epoch run): page uses, hits, requests, modeled seconds and each resource's service seconds (requests, bytes, cores, memory: the largest binds). Seconds are zero without a cost model.
